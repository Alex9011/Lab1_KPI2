# Специфікація — бібліотека

## Намір і межі

Описати каталог та історію видач паперових книг однієї бібліотеки. Book — конкретне видання, Copy — фізичний примірник. Різні видання мають різні book_id. Без бронювання, штрафів, філій, SQL та ORM; записи, потрібні для історії, не видаляють.

## Сутності й атрибути

- **Book:** `book_id` — PK; `title` — назва; `publication_year` — рік видання.
- **Author:** `author_id` — PK; `full_name` — ім'я автора.
- **Copy:** `copy_id` — PK; `inventory_number` — інвентарний номер (UK); `book_id` — FK → Book.book_id.
- **Member:** `member_id` — PK; `full_name` — ім'я читача; `email` — контактна адреса.
- **Loan:** `loan_id` — PK; `member_id` — FK → Member.member_id; `copy_id` — FK → Copy.copy_id; `borrowed_at` — видача; `due_at` — строк повернення; `returned_at` — фактичне повернення.

## Зв'язки

- **Book ↔ Author:** 0..* з обох боків; анонімні видання й автори без книг у каталозі дозволені. Прямий M:N без власних атрибутів.
- **Book → Copy:** 0..*; кожний Copy належить рівно одному Book. Опис можна додати до надходження примірників.
- **Member → Loan:** 0..*; кожний Loan належить рівно одному Member. Новий читач може не мати видач.
- **Copy → Loan:** 0..* історичних видач; кожний Loan стосується рівно одного Copy. Loan має власні дати й тому є асоціативною сутністю-подією.

## Критерії прийнятності

- **C1:** рівно 5 сутностей і 17 зазначених атрибутів; назви збігаються з моделлю, Book описує видання.
- **C2:** усі PK/FK — UUID; publication_year — int; три дати — datetime; решта — string. inventory_number унікальний у бібліотеці. email не є UK: спільна адреса дозволена. Імена, назви й пара title + publication_year не є ключами. Повторна видача пари member_id + copy_id отримує новий loan_id.
- **C3:** мінімуми й максимуми обох кінців зв'язків відповідають опису; технічної BookAuthor немає.
- **C4:** атомарні атрибути; 3NF на рівні атрибутів сутностей — без часткових і транзитивних залежностей неключових атрибутів. Описи книг/читачів у Loan не дублюються; доступність обчислюється.
- **C5:** лише returned_at необов'язковий. Дати — UTC; due_at > borrowed_at; returned_at ≥ borrowed_at, якщо заданий. Інтервали [borrowed_at, returned_at) одного Copy не перетинаються; відсутнє повернення означає відкритий інтервал. Максимум одна неповернута видача на Copy. Ці правила доповнюють ER-кардинальності.
- **C6:** Mermaid та SVG узгоджені; уточнення починаються зі spec, сліду аудиту збережено; фізичної схеми немає.
