# Фактичний аудит

Порядок роботи: записано [початкову spec](versions/00-spec.md) → сформовано [першу модель](versions/00-diagram.mmd) → виявлено три прогалини нижче → послідовно уточнено spec і повністю сформовано наступні версії моделі. Початкова структура не потребувала штучних змін кардинальностей. 

## 1. Що ідентифікує Book — C1

**Проблема:** початкова spec називає Book книгою, але publication_year має сенс для конкретного видання. Для твору з перевиданнями незрозуміло, яке значення зберігати.

**Фідбек:** визначити Book як видання; різні видання мають різні book_id, назва та рік не є унікальним ключем.

**Уточнення spec → модель:** [01-spec](versions/01-book-spec.md) → [01-diagram](versions/01-book-diagram.mmd); додано пояснення ключа Book.

**Перевірка:** видання одного твору за 2020 і 2025 роки отримують різні book_id; три фізичні книги одного видання — три Copy одного Book. Поточні spec C1 та модель узгоджені.

## 2. Унікальність інвентарного номера — C2

**Проблема:** модель 00 містить inventory_number UK, але початкова spec не встановлює унікальність. Позначка ключа не має явного бізнес-правила.

**Фідбек:** зафіксувати унікальність inventory_number у бібліотеці; окремо уточнити, що email не унікальний, а member_id + copy_id не є ключем історії.

**Уточнення spec → модель:** [02-spec](versions/02-keys-spec.md) → [02-diagram](versions/02-keys-diagram.mmd); уточнено область дії UK.

**Перевірка:** два Copy з однаковим inventory_number заборонені; два Member зі спільним email дозволені; повторні видачі тієї самої пари мають різні loan_id. UK у моделі рівно один.

## 3. Часова цілісність видач — C5

**Проблема:** returned_at описано як необов'язковий, але не визначено допустимий порядок дат і неперетин видач. Кардинальність 1:N не забороняє одночасні видачі одного Copy.

**Фідбек:** додати UTC, due_at > borrowed_at, returned_at ≥ borrowed_at; інтервали одного Copy не перетинаються, максимум одна відкрита видача.

**Уточнення spec → модель:** [03-spec](versions/03-time-spec.md) → [03-diagram](versions/03-time-diagram.mmd); додано коментар часового правила й пояснення due_at. Історичну 1:N збережено.

**Перевірка:** інтервали 10:00–12:00 та 11:00–13:00 одного Copy заборонені; 10:00–12:00 та 12:00–14:00 дозволені. Повернення раніше видачі заборонене. Ці правила перевіряються за spec, не самою нотацією ER.

## Підсумкова перевірка

Кореневу spec стисло оформлено без зміни правил версії 03. Перевірено 5 сутностей, 17 атрибутів, 5 PK, 3 FK, 1 UK і 4 зв'язки; тип кожного FK збігається з цільовим PK. Рендер читає ті самі блоки атрибутів і зв'язків із diagram.mmd. Залежності для 3NF наведено в ADR. SQL/ORM, сполучної BookAuthor та збереженого похідного стану доступності немає.
